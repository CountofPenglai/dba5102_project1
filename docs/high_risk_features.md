# 高赔付风险分类：特征与标签入口

本入口仅准备特征、训练/评分标签及审计。用户后续已授权训练，q97.5和q95的GBDT对照及固定倍率试验已通过独立入口完成，见[训练说明](high_risk_training.md)。以下保留数据准备阶段的标签规则和审计统计。

## 高风险标签

默认主标签 `high_risk` 指向 `high_risk_unit_q975`：每BTC最终赔付严格超过当天合法历史中同方向×合同期限的97.5分位。方向×期限至少80笔，否则退回同方向；方向至少60笔。零赔付参与历史分布，不删除；阈值为0或没有足够历史时标签为NA，不当作正常订单。

同时提供 `high_risk_unit_q950`、`high_risk_cash_q975`、`high_risk_cash_q950`。前者辅助观察较宽尾部，后两者识别单笔平台总赔付；两种经济目标不混成一个标签。`config/high_risk_features_v1.json` 的 `primary_target` 为 `unit`，仅在明确改变研究目标后才切换成 `cash`。

每日D的阈值只使用 `[D−30d,D)` 创建、且 `closedAt<D` 的历史订单，训练和当日评分共用同一套阈值。阈值每日重新拟合，因此同一历史订单在不同训练日的标签可能变化。不要在全开发集上生成永久标签再随机切分；97.5分位也不意味着未来样本或全期分组后恰有2.5%正例。

最终赔付作为监督目标的来源，允许参与标签构造；赔付值、标签、阈值、实际关闭时间均不得作为输入。高风险标签并不证明创建时可预测，也不等于高风险行情标签。

## 输入特征

固定32项，字段字典由代码生成并随审计输出：

| 类别 | 数量 | 内容 |
|---|---:|---|
| 合同与保额 | 5 | 方向、合同/剩余期限的对数、承保BTC对数、方向对齐moneyness |
| 方向收益 | 3 | 60/240/1440分钟收益，Put下跌为正、Call上涨为正 |
| 方向波动 | 6 | 60/240/1440分钟风险方向与反方向RMS |
| 波动变化与路径 | 6 | 波动增量、60/240波动比、双向最大分钟跳变、双向有序最大回撤/上涨 |
| 市场成交活动 | 4 | 15/60分钟实际成交频率、相对先前24小时频率、主动成交方向压力 |
| 平台订单活动 | 8 | 同/反方向15/60/240分钟订单数、近期/此前活跃比、历史覆盖标志 |

只使用创建时已完成且连续的分钟行情；最后K线时间和波动与canonical输入核对。平台窗口为 `[t-W,t)`，当前和同刻订单排除，不用赔付、结算或Base是否存在来筛选创建记录。原始平台日志经过提供方筛选且无唯一订单ID，因此它不是完整全平台需求。

不加入保费/markup、官方Base的填充值、实际持有时间、客户身份猜测或某天是否为事后峰值。外部盘口、OI、DVOL暂不加入，以保持完整4–6月日期覆盖。

**缺失规则：**平台日志覆盖不足时保留NaN；活动比的此前频率为0、市场主动成交压力的成交金额为0时也保留NaN。不能将无定义比率任意填0。其他特征必须有限；如果后续模型需要插补，插补器只能在当天训练数据拟合。本轮不拟合插补器、标准化器或分类器。

## 命令与程序入口

项目目录下：

```sh
# 只展示固定设置与字段，不读取数据、不训练、不写运行结果
.venv/bin/python -m pp_models.high_risk_data plan

# 生成关键数据审计；不训练
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m pp_models.high_risk_data audit --run-id NEW_ID

# 独立重建汇总和样例特征，核对所有来源哈希
OPENBLAS_NUM_THREADS=1 .venv/bin/python -m scripts.verify_high_risk_data --run-dir outputs/feature_engineering/NEW_ID
```

程序使用 `build_high_risk_features(pool, market, events)` 构建内存特征表；随后 `prepare_day(pool, features, day, settings)` 返回分开的 `train_X/train_labels/score_X/score_labels`，以及该日标签阈值。`train_labels.high_risk` 是未来分类训练目标；标签NA必须明确处理，不得转成0。API使用开发pool，不接受七月训练/评分日。

唯一日期来源仍为 `config/validation_protocol_v2.json`，canonical文件和旧研究结果不改。输出放在 `outputs/feature_engineering/<run-id>/{metrics,provenance,reports}`；不导出逐笔X/y、预测或模型。保存训练支持度、标签覆盖、缺失统计、字段字典、队列哈希和源码快照，可以按来源重新生成内存数据。

## 当前结果

4,514笔开发订单生成32项特征；4–6月评分4,074笔、88个有订单日。默认97.5分位单位标签产生Call74、Put95笔高风险，合计169笔（4.15%），分别分布在29个日期。它们覆盖实际赔付总额的35.90%；总赔付97.5辅助标签247笔，覆盖61.25%。这是事后标签覆盖，不是模型预测命中率。

训练窗口内默认正例Call为3–35笔（中位17）、Put为5–26笔（中位15）；分别有13/88、20/88个窗口不足10个正例。低样本日如何回退需在训练设计中显式确定，不因为已有32项特征就使用更深的树。

所有评分标签均可用。385个缺失特征单元来自活动比零分母/历史不足，其中379个为平台活跃比，另6个为最早记录的历史计数不足；没有任意填0或删除订单。
