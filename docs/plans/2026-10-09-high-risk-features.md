# 高赔付风险特征与标签实施计划

> **For agentic workers:** 按本会话已授权范围在当前研究目录内执行，先完成特征与标签，不训练 GBDT 或执行抬价。使用 TDD 与完成前核验。

**Goal:** 为后续高风险分类器提供统一、无事后特征泄漏的输入与高峰赔付标签。

**Architecture:** 新增独立特征/标签模块与 `plan|audit` 入口，复用不可变开发数据、已完成行情及创建事件读取器。每日训练标签阈值只拟合过去30天、当日之前已结算的历史；同一份阈值用于该日训练标签与评分标签。只保存汇总与来源，完整 X/y 在内存按日构建。

**Tech Stack:** 现有 Python / pandas / NumPy，暂不调用任何估计器 fit。

**Spec:** 用户本轮“先做特征工程、最终大额赔付标高风险、阈值较高聚焦训练高峰”；保留此前4–6月滚动协议与7月封存。

## 固定规则

- 主标签为每BTC赔付超过历史97.5分位；95分位为辅助对照。单笔总赔付同样生成两个辅助标签。若用户另选总赔付优先，仅切换主标签指向，不混合不同目标。
- 按方向×合同期限拟合阈值；组内至少80笔，否则退回同方向，方向至少60笔。不得跨方向借用。零阈值或历史不足时标记不可用，不将未知当0。
- 使用严格大于阈值；分位数在线性插值下计算，零赔付也参与历史分布。分组下的97.5分位不保证全期恰有2.5%正例；不同日标签定义可随历史变化。
- 所有期限分组阈值变化与回退均输出关键汇总。高峰指条件单位赔付尾部，不是指定某几个日期为正例。
- 输入涵盖方向与期限、moneyness、承保量，多窗口方向收益和半波动，波动变化/跳变/回撤，市场成交频率与方向买卖压力，以及平台分方向订单频率。不加入客户身份猜测、实际保费、实际持有期、最终赔付、关闭价格或事后日期标签。
- 不使用外部盘口/OI/DVOL，以保持完整日期覆盖。原始Base不插补；本轮核心特征不依赖Base。
- 平台活动采用 `[t-W,t)`，当前与同刻记录均排除；最早日志覆盖不足保留NaN并记录。市场成交频率比和主动成交压力在分母为0时也保留NaN，不将无定义比率填0；字段字典明确每项缺失规则。其余特征必须有限。保留元数据中的可用时间作核验，不作为模型输入。
- 使用唯一v2验证协议，仅读开发六表与7月前行情/订单前缀。当前分支有既有未提交研究变更，不建立丢失这些依赖的新工作树、不提交推送。

## Review Focus

- 今日或尚未结算的大额标签不得改变历史阈值：边界与未来标签变异测试。
- 所有输入必须对未来行情、关闭时间和赔付变异保持不变：真实特征构造测试。
- 极少期限组、未见方向、全零赔付、阈值并列必须明确返回回退/未知/非高风险状态。
- 历史订单可重复用于不同训练日，但评分订单必须只计一次；分位数正例嵌套关系必须成立。
- 输出只能包含聚合统计与来源，不能意外导出逐单输入、标签或模型。

## 决策与进度

历史可行性检查只使用各滚动训练窗口，未用评分标签选阈值。99分位最早Call窗口只有1笔正例，因此保留97.5主标签、95辅助；97.5窗口的单位赔付正例中位Call17/Put15笔，仍需在后续训练中限制复杂度。主/辅助按当前已有单位风险研究默认设置。

11项新增测试先失败后通过，项目181项测试通过；独立核验768组训练/评分汇总和24笔×32项特征。独立审查无Critical/Important；补齐市场活动零分母保留NaN的文档例外，代码行为未改。初轮核验完成后仅更新文档，最终按同一设置重新保存来源快照，不用新结果改阈值。
