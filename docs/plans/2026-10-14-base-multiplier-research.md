# 官方 Base 倍率修正：已确认研究方案与本轮统计审计

确认日期：2026-10-14。用户认可在官方 Base 上输出动态倍率，要求先记录方案并分析旧数据，不训练、不使用新的官方验证集。本文替代新一轮研究中“默认每天取得新赔付标签”的假设，不改写历史实验或原 Put 组合冻结版本。

## 1. 目标与接口

- 官方正式项目说明允许 `Final Premium = Base Premium × Pricing Multiplier`，并允许按订单提交倍率。当前研究输出 `m(X)`；Base 用于历史损失计算和评价，不作为倍率预测输入。
- 研究问题：下单时可知的合同和市场状态能否稳定解释 Base 的偏差，并支持小幅修正；不是直接拟合历史成交价或无条件加价。
- 首轮只修正 Put，Call 的倍率固定为 1。比较 Put 自身增量，不能把 Call 从 H0 改回 Base 的收益归功于 Put 修正。
- Base 缺失的订单不能用于直接拟合 `Base × m` 或与 Base 评分；单列覆盖率，不插补或删除后隐瞒。无 Base 时仍可输出不依赖 Base 的倍率，但没有本地最终报价和误差评价。
- 新官方验证集继续封存：不读订单内容、不选择特征、不设阈值、不调参。新版 BTC 文件仅允许读取与旧实验哈希一致的历史前缀。

## 2. 未来训练目标（本轮不执行）

`y = realizedProfit_USDC / quantity_BTC`，预测 `y_hat = Base × m_theta(X)`。真实零赔付和大额赔付全部保留，不只拟合正赔付、不直接回归 y/Base、不截断标签。

目标为 `mean(((Base × m_theta(X) - y) / s_train)^2) + lambda × ||theta||²`。尺度只由合法训练数据确定，参数向零收缩对应倍率向 1 收缩。平方误差负责学习预期赔付，MAE、尾部和现金偏差用于筛选；不额外加入保守加价或把赔付误差等同于真实利润。

初版为低维倍率回归：`m = 1 + clip(g_theta(X), -delta, delta)`。主方案 delta=0.10，delta=0.20 仅作事先约定的敏感性对照；训练和评价均使用受限倍率。具体正则强度、回退支持门槛和优化实现尚未授权训练，后续开训前统一固定，不依据本轮分组最优结果追加大网格。

对照依次为：Base（倍率1）、Put常数倍率、Put合同条件倍率、Put合同＋市场倍率。H0和旧Put组合保留无反馈回放参照。

## 3. 特征

- 合同层：剩余期限对数、按历史总波动与剩余期限标准化的方向价内程度。
- 市场层：Put过去240分钟下行RMS、过去60分钟方向收益经历史总波动标准化。未来研究Call时可对应上行风险。
- 60/240相对方向波动只作诊断；不独立触发加价。若主特征有增量，再单独讨论绝对水平与相对变化的交互。
- 暂不加入平台订单频率、保单数量加价、Base数值、成交价、markup、实际结束时间、未来行情或验证期赔付反馈。
- 行情仅取下单前完整分钟；标准化与支持区间只取训练历史。支持不足或超出支持范围时优先倍率1，具体规则在模型实现前固定。

## 5. 采用标准

- 想替代H0须在相同评价协议下同时改善RMSE和MAE；只胜Base先作为候选。
- 普通Put不能为尾部抬价付出明显MAE损失；尾部RMSE和累计低估沿用相对Base最多恶化2%的研究工作容忍度。
- 保留金额偏差约束，并分别查看Call/Put和累计高估、累计低估，不用方向抵消掩盖风险。
- 对好候选进行按日分块区间、删除单日/连续7日/单一期限的评分检验；特别检查移除24h后的收益和2h/4h普通Put。
- 点估计改善而95%区间跨0则标记“增益尚不确定”；不把局部收益宣称为全面有效，不把研究阈值说成官方规则。

## 6. 本轮 Base 描述性审计：执行前固定口径

### 范围与输入

- 只使用已经冻结的 `outputs/preprocessing` 旧训练数据产物；4–6月共同评分2,953单，7月2,541单。保留全部零赔付/正赔付，不按真实尾部筛选定价群体。
- 新行情只读取旧7月截止前的完整K线（开盘严格早于 `2026-07-31T17:11:00Z`），其SHA256必须等于此前正式7月运行记录。边界行只识别时间，不用新时期价格。
- 不调用任何模型 `fit`、预测或参数搜索入口。仅构建因果特征和计算Base误差。

### 特征与分组

1. 方向分别报告，重点Put；期限使用标称小时数，价格位置的标准化使用下单时剩余分钟tau。
2. 令 `d=+1(Call), -1(Put)`，`sigma240=sqrt(mean(过去240个分钟对数收益²))`。
3. 方向价格位置 `position=d×log(S/K)/max(sigma240×sqrt(tau),1e-6)`；数值大表示更靠近价内，不能把近ATM的小差别说成深度价内/价外。
4. 方向绝对波动为对应上行/下行240分钟RMS，分母含全部240个分钟。
5. 方向趋势 `trend=d×log_return_60m/max(sigma240×sqrt(60),1e-6)`。固定三组：`<=-0.5`有利方向、`(-0.5,0.5]`近中性、`>0.5`不利方向；“有利/不利”均相对赔付方风险。
6. 价格位置、绝对方向波动、相对方向波动60/240，按4月前已结算共同样本、各方向的1/3与2/3分位固定分箱。4–7月不重估阈值，阈值不用赔付数值。
7. 单因素：期限、价格位置、绝对波动、趋势、相对波动；Put双因素：期限×价格位置、期限×绝对波动、价格位置×绝对波动、绝对波动×趋势。不开三重格子搜索。

### 关键统计与稳定性

- 误差 `e=Base-y`：正值高估、负值低估；报告均值、RMSE、MAE、Base与实际均值，现金偏差`sum(q×e)`，累计高估与累计低估分别汇总。
- 报告订单数、独立创建日数、零赔付占比、BTC数量、Base覆盖率。每月分组至少30单且5个创建日才视为“支持充分”；不足仍保留统计并明确标记。
- 月内按完整日历日进行7天环形块bootstrap，2,000次，固定种子20261014；均值偏差区间至少1,900次有效重采样，否则不发布区间。空交易日保留，重采样聚合后按订单数作分母。区间是探索性点区间，未经多重比较校正。
- 逐月比较偏差符号、支持度、区间及删除连续7日后的偏差范围（至少剩10单才计算）；未有4个月充分支持的格子不称跨4月稳定。
- 补充Base处MSE/MAE对共同倍率的局部斜率：`2×mean(Base×e)`、`mean(Base×sign(e))`。仅诊断“向上/向下微调”的局部目标方向，不拟合倍率、不评分任何新候选；平均偏差稳定不保证平方误差修正方向一致。
- 对最有意义的Put状态进一步报告固定期限结构下的偏差，区分状态关联与合同混合；仅有共同充分支持格子时计算，不外推缺失格子。
