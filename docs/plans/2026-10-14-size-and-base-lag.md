# 大单赔付与Base滞后：分析计划

> 执行方式：当前会话直接分析，沿用已有只读数据保护和结果复核流程；不训练、不改价、不提交。用户已授权本轮研究，无需重复批准。

**目标：** 区分承保量与单位风险，验证“先赔后涨”是否超出订单构成、时间归属和单次冲击的解释。

**架构：** 复用不可变预处理及因果行情特征；新增独立统计脚本、关键汇总和报告。只读旧4–7月，所有新官方验证文件封存。

**技术：** pandas/numpy，7天日历块bootstrap 2,000次；无预测模型。

**范围：** 全部risk合格订单为大单主样本，含Base共同样本为敏感性；Base时序只用共同样本。7月已被查看，不能称为独立确认。

## 任务与口径

- [x] 大单：每日用此前30天创建且当日前已结算的同方向×精确期限数量q90（至少30单，否则回退同方向）；固定4月前方向q90作敏感性。不得按最终现金赔付定义大单。
- [x] 赔付口径：发生赔付比例、每BTC赔付、赔付/入场BTC名义价值、历史q90高单位赔付比例、现金赔付占比；赔付/记录保费及赔付/Base分别明确分母，不当作赔付概率。
- [x] 控制：方向分开，同创建日×精确期限匹配；加价格位置、加方向波动分组两层敏感性；日内按可比组总订单数加权，日期等权。报告覆盖、月度、删7天、排除6/24–25、区间；精细匹配的样本损失不得隐瞒。
- [x] 滞后：分别按创建日和关闭日，比较最终赔付和新成交订单Base的−3至+3日相关；同时看现金、单位、波动尺度归一化、固定0.5h/4h期限及近ATM。缺单日保留缺失，不向前填充；正lag明确代表Base在后。
- [x] 独立市场事件：完成的小时方向收益超过过去30天同方向小时收益q99，q97.5作敏感性；取首次触发、同向事件至少间隔72h；事件时间为该小时结束。窗口为[-24,-4)、[-4,-1)、[-1,0)、[0,4)、[4,24)、[24,48)小时。首末边界不完整排除，窗口选择不看赔付。
- [x] 事件比较：每事件等权，比较实际单位赔付、Base和Base/现价/√剩余分钟；共同精确期限×价格位置格控制前后构成，报告配对事件数、各月方向、删单事件范围。补同事件、共同合同格的平衡面板，禁止拼接不同事件集合为响应曲线。事件聚类区间只为探索，不宣称因果或最优延迟。
- [x] 必要核验：大单阈值只能来自过去、数量与现金口径恒等式、滞后符号及日历缺口、事件不重叠、匹配分组的Simpson反转。独立重算关键数值并保护旧产物。
- [x] 汇总：将统计重复性、金融机制合理性和可用于定价的证明分开；引用OIC期权定价资料、Engle波动研究和Pan/Poteshman订单信息研究，不将股票期权证据直接移植为本平台结论。
