# 报告项目架构清理

用户要求：清除报告无关的旧模型、探索、记录、结果和过时分割；将旧模块中仍需引用的函数重构出来，只保留必要部分。

范围：当前main工作树；原始资料和其他研究分支不修改。报告99个既有配置、当前汇报和结果、官方公告来源包、必要审计与复现工具保留。删除可从Git恢复的旧代码和旧版本化结果，不以另一份archive目录继续堆积。现有报告样本及指标不变，不使用新官方验证。

## 实施

1. 数据：改为features/targets/metadata统一数据池，唯一训练验证角色来自现有4月训练、5–7月周更协议。旧文件仅由显式迁移工具读取并校验，模型不再提供旧split接口。迁移保留已确认报告队列，不能为清理而补回原预处理排除订单；新的原始数据构建与报告队列复现明确区分。
2. 公共能力：提取H0、尾部上下文、评分与重采样、市场前缀读取、运行归档及独立核验。剥离报告对旧GAM、静态分布、残差、旧两阶段分支及旧运行链的依赖。仅保留统一训练入口，单项配方保留其预测逻辑，不保留重复旧CLI。
3. 清理：删除无关代码/测试/配置/记录、旧结果目录、旧分割协议；更新依赖列表、README和交接索引。公告日历及来源维护保留，旧日期协议分析入口移除。保留一套当前关键统计，不覆盖已有结果的来源事实。
4. 验证：先测试平面数据往返、内容篡改、时间边界/未来标签、必要公共接口与断开旧依赖；保留相关模型测试。私有池迁移逐列相等，99配置完整前向运行对照报告汇总。新运行及旧归档核验路径明确区分；测试、文档链接和独立代码审查通过后完成。不自动提交推送。
