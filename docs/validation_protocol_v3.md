# 唯一验证协议 4月训练与5–7月周更验证

[config/validation_protocol_v3.json](../config/validation_protocol_v3.json)是当前日期及角色的唯一来源，由`pp_data.config.load_protocol`加载，模型公共层`pp_models.validation`统一筛选历史与尾部参考。不再保留其他可执行分割协议。

## 时间与信息边界

| 项目 | 当前设置 |
|---|---|
| 最早训练创建时间 | 2026-04-01 00:00:00 UTC |
| 验证区间 | 2026-05-01 00:00:00至2026-07-31 17:11:48 UTC，右端不含 |
| 参数更新 | 从5月1日起连续每7日；月界不重置 |
| 每次拟合历史 | 创建于[max(4月1日, 更新时刻−30日), 更新时刻)，且实际结算严格早于更新时刻 |
| 周内 | 参数冻结，但允许定价时已知行情变化影响输入 |
| 7月身份 | 已见滚动验证，无独立test分区 |
| 新官方验证 | 禁止读取 |

验证标签只在结算后参与之后的更新。7月1–2日继续使用6月26日参数；不能用7月初汇总结果反选上周权重。动态混合保留4月前向热身和14/30日已结算前向误差窗，不读取同期未来误差，也不按月份拼接最优比例。

数据以一个平面池储存；模型按上述时间查询。当前报告固定比较4,640单，5/6/7月分别726/1,373/2,541单，有12个非空验证更新批次。旧报告样本中的跨月结算排除仍保留，属于队列历史局限，详见[数据流程](data_pipeline.md)。

## 评分与尾部

主指标优先RMSE，MAE监控常规订单代价。月等权RMSE为三个单月MSE均值再开方；另列全期逐单RMSE和MAE，避免订单数量变化隐藏退化。实际赔付及预测均为USDC/BTC，现金指标额外乘以各订单BTC数量。

每月初使用4月起、当时已创建且已结算的历史，计算方向×期限q90阈值；组内不足30单回退同方向。预测时不使用未来尾部身份，评价时才按实际赔付是否超过该阈值标为尾部。无可用阈值单列，不填0。

工作风险约束不是官方规则：分别相对Base/H0核对方向尾部RMSE、累计逐单少估与净金额偏差；前两项容许恶化最多2%，净金额偏差绝对值不得扩大。不得只看净额而掩盖正负误差抵消。完整支持、分月风险和方向结果均单列。

不确定性采用3/7/14日块、每档2,000次按月循环重采样，及删除连续7日诊断。复算已产生的前向损失，不在重采样中重新拟合。257个既有配对的同时区间也不能覆盖项目所有历史试验。

## 结论边界

5–7月经过多轮模型选择。严格前向训练防止未来信息泄漏，但不等于独立盲测。当前周更还需要真实结算标签反馈；无标签官方环境的兼容性、独立测试和业务利润均未验证。
