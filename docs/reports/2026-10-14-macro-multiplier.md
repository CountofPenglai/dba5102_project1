# 公告倍率首轮结果：轻微改善未通过采用条件

日期：2026-10-14。用户授权的共享时间结构、方向差异强收缩、样本不足回退1已实现并训练。最终结果目录：`outputs/model_studies/macro_multiplier_20261014_v2/`。仅旧数据，无新官方验证访问；不替换现有模型，不追加调参。

## 1. 结果与取舍

**本轮不采用公告倍率作为最终模型。** 开发期相对Base的RMSE/MAE分别降低0.032/0.040 USDC/BTC，幅度很小，仍不及同协议H0；7月MAE下降0.091，但RMSE升高0.064。两个时期Call和Put的尾部单位误差都略高于Base，净金额低估也扩大。

| 阶段 | 模型 | RMSE（USDC/BTC） | MAE（USDC/BTC） |
| --- | --- | ---: | ---: |
| 4–6月开发 | Base | 292.5738 | 182.1307 |
| 4–6月开发 | H0 | **290.9724** | **165.7779** |
| 4–6月开发 | 公告倍率 | 292.5422 | 182.0907 |
| 7月压力复查 | Base | **275.3845** | 185.2542 |
| 7月压力复查 | H0 | 301.2650 | 206.0353 |
| 7月压力复查 | 公告倍率 | 275.4485 | **185.1633** |

开发主指标按月等权：各月MSE均值开方为RMSE，各月MAE取均值；开发2,953单、7月2,541单，各模型完全相同。**本轮H0也是每月初冻结，不是每日滚动更新**，所以7月301.2650不应与此前每日更新的288.3152混用。

这轮证明了日历修正能够严格按历史信息实施，但尚未证明其能稳定改善Base的赔付估计，尤其没有验证尾部优化能力。市场公告后波动较强，与Base仍需上调多少，是两个不同问题。

## 2. 实际训练了什么

固定方案见[执行计划](../plans/2026-10-14-macro-multiplier-execution.md)及[配置](../../config/macro_multiplier_v1.json)。本轮没有叠加以前未通过的Put倍率或加入额外安全余量。

- 倍率预测入口只用创建时刻、计划剩余期限、方向与公共日历，输出倍率；不输入Base、赔付或实际结束时间。Base与真实赔付只在训练目标和评分中使用。
- 三个共享时间基函数：公告前60分钟的未来保障重合比例；是否跨尚未发生的发布瞬间；公告后未来保障对指数衰减核的覆盖。半衰期固定60分钟、截止主要公告后240分钟，未调这些时间参数。
- FOMC声明和记者会一个事件组，瞬间跨越取“任一”，公告后核取上包络，不相加；多主要事件同时覆盖或历史证据未知则回退1。
- 3个共享系数、每方向3个偏移，无截距。总倍率限制0.95–1.05，方向偏移最多±2个百分点并包含在总上限。约束施加在整个特征立方体顶点，不只约束训练点。
- 共享支持逐基函数要求至少5事件、30单、2个公告月份；方向项至少8事件、60单、3个月，且共享项已启用。支持不足的项固定0，没有可用项时严格为1。
- 训练含零/正赔付，损失为事件等权、事件内订单等权的归一化平方误差，加L2；不截掉大赔付、不回归赔付/Base。共享正则仅比较1/10/100，方向惩罚为其10倍。
- 4/1、5/1、6/1各用此前已创建且已结算的旧历史拟合，月内无标签反馈；公告必须已经发生。**下一月起点可以使用上月已结算历史**，不是4/1冻结三个月。H0只用起点前30天，公告修正使用全部合法历史。7/1拟合一次并冻结到旧7月末。
- 在4–6月MAE不劣于Base的配置中选择月等权RMSE最低者，选中最强收缩100；选择落盘后才打开旧7月。没有根据7月重选、改门槛或搜索新的核。

公共日历固定历史补证快照`20261014T123002Z`；旧市场仅既有哈希前缀。`no_identified_event`是回溯版本没有识别到相关事件，**不是已认证当时一定无事件**；仍回退1。此次历史证据不等于完整日历修订档案，实时使用仍需要维护当时有效版本。

## 3. 支持门槛实际限制了哪些修正

| 起点 | 历史事件暴露订单／事件 | 共享项 | 方向项 | 当月实际调整订单 |
| --- | ---: | --- | --- | ---: |
| 4月1日 | 34／4 | 全部不启用 | 全部不启用 | 0 |
| 5月1日 | 109／7 | 三项启用 | 全部不启用 | Call13、Put12 |
| 6月1日 | 134／8 | 三项启用 | 仅Call公告后项 | Call29、Put22 |
| 7月1日 | 185／9 | 三项启用 | Call/Put均仅公告后项 | Call137、Put102 |

历史“事件暴露订单”包含跨公告、公告前保障重合及公告后新订单，不等于此前只有16笔的4月前“跨公告”子集。每个基函数分别统计支持。例如4月初公告后暴露已有32单，但只有4事件，仍不启用；没有通过放宽门槛强行产生修正。

开发仅调整76/2,953单（2.57%），实际来自5月CPI及6月FOMC两个独立事件；4月完全等于Base。5月非农、6月非农及6月CPI的Base缺口使它们不能支持本次Base倍率训练和评分，不能把这些缺失解释为风险低。

7月调整239/2,541单（9.41%），来自3次事件。全部调整均为下调，没有订单被上调。5月最低倍率0.95319，6月和7月最低0.95；7月Call/Put平均倍率分别0.99806/0.99818，这是包括未调整订单后的整体平均。7月方向偏移的最大实际绝对贡献仅0.0984/0.0599个百分点，主要变化来自共享项。

## 4. 为什么学到的是下调，而不是公告加价

合法历史中，若干事件暴露订单的Base明显高于最终赔付。5月起点有7个事件组，其中6组在两方向合并后的平均Base偏差为正；3月非农一组约+608.55 USDC/BTC。到7月起点，9组中仍有7组为正，6月FOMC合并后约−13.75。

这些均值用于解释历史构成，优化本身还受Base尺度、曝光基函数及平方损失影响，并不是对正负事件投票。事件内有多少订单不能改变事件的总训练权重，但**这仍不能消除早期高估事件对少量历史的影响**。最强正则也未将所有下调消除：在某些完全暴露状态，总修正达到预设−5%边界。

因此，模型学到的是“历史这些合约在事件附近的Base略偏高”，并非“公告降低市场波动”。当前训练证据不能证明公告普遍应降价，也不能为了符合“公告应加价”的预期把符号改成只涨不降。

## 5. 改善来自哪里，尾部有没有受损

下表采用每个阶段内的**订单等权尾部RMSE**，不是开发主指标的月等权。尾部按每月起点历史的方向×标称期限q90确定，不足30单回退方向；所有模型共享阈值，标签只作评分。

| 阶段／方向 | 尾部订单 | Base尾部RMSE | 公告倍率尾部RMSE | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 4–6月 Call | 107 | 689.1223 | 689.1360 | +0.0137 |
| 4–6月 Put | 183 | 917.3259 | 917.4875 | +0.1616 |
| 7月 Call | 171 | 673.0755 | 674.9586 | **+1.8830** |
| 7月 Put | 83 | 720.2940 | 720.5246 | +0.2306 |

四组尾部MAE也都略升。虽然尾部退化没有超过既定2%工作容限，但这不构成尾部改善的证据。7月较明显的损失来自Call：其全部订单RMSE/MAE比Base增加0.4722/0.1508；Put全部订单则降低0.4124/0.3611，收益主要在普通订单，Put尾部仍略差。

开发期，5月CPI和6月FOMC的Call均受益于下调，Put在这两个事件上却均退化。7月CPI及非农的Call下调有害，FOMC的Call有利；Put在7月三个事件的整体误差均下降。**这是不同方向/事件的Base偏差变化，不是已经稳定学出的方向差异**，因为强收缩后的方向项很小。

| 现金指标 | 4–6月 Base → 公告倍率 | 7月 Base → 公告倍率 |
| --- | --- | --- |
| 净金额偏差（预测−真实） | −23,692.12 → −23,738.82 | −31,078.71 → −31,375.71 |
| 累计低估金额 | 62,768.45 → 62,778.41 | 71,362.59 → 71,527.78 |

单位为USDC。下调使整体净低估分别扩大46.71和297.00，绝对净偏差约束两期均失败。开发Put普通订单MAE也略高于Base；因此即使开发整体双指标有微幅改善，也不满足采用条件。

## 6. 稳定性与小样本限制

完整输出包含3/7/14日历天块、每种2,000次的配对区间；以下列7天块结果，增量均为公告倍率减Base：

| 阶段／范围 | RMSE增量及95%区间 | MAE增量及95%区间 |
| --- | --- | --- |
| 开发整体 | −0.0316，约[−0.0913, 0] | −0.0401，约[−0.1131, 0] |
| 7月整体 | +0.0641，[−0.2107, +0.4970] | −0.0909，[−0.2018, +0.0321] |
| 7月Call | +0.4722，[−0.1581, +1.0533] | +0.1508，[−0.1557, +0.5151] |

开发大量抽样没有抽到实际修正的两次公告，区间上界出现0，不能解读为充分证明稳定增益。7月Put单独的7天块区间较好，但只来自3次事件，且整体、尾部与金额约束未通过；未作多重比较校正，也不是新的独立验证。

整事件删除进一步显示收益集中：开发删掉6月FOMC后，整体MAE改善从0.0401缩至0.0054；7月删掉FOMC后，MAE增量从−0.0909变为+0.0083，优势消失。删除CPI后7月RMSE增量又从+0.0641转为−0.0671。这里删除的是已冻结预测中的整组订单，**没有重训**，不能冒充独立留事件验证。

## 7. 当前应保留与停止的部分

保留公共日历、历史证据保护、未来保障积分、事件分组、支持回退和严格冻结评估入口。这些基础设施有效，之后可以服务其它已获授权的实验。

本轮共享公告倍率不采用，不以这组结果自动改成只涨、放宽门槛、扩大上下限或按7月挑方向。现阶段主要缺口是：可评分事件过少且有Base缺失；事件附近Base高低估跨方向变化；日程本身不能描述公告意外程度和之后的价格方向。它是潜在辅助信息，还不是可靠的极端赔付保护机制。

运行拒绝覆盖已有目录。首轮`macro_multiplier_20261014`保留审计历史；独立审查发现历史入口曾用实际结束时间筛选预测订单，现已改成只按创建时间生成预测、在评分时才判断是否结算。未知结束时间的真实测试先失败后通过；最终v2和首轮的各组评分完全相同，查询接口边界更明确。

10项新增测试及全项目393项测试通过。独立核验不调用模型fit/predict，以另一套数值积分检查5,934条日历特征，按保存参数重算10次倍率拟合的支持、损失与全域约束；独立回放234行Base/H0/倍率统计及24个7天块的整体/Call/Put双误差区间。没有声称所有3/14天或普通/尾部区间均另行重算。

原冻结Base/H0的开发24组、7月12组全部复现；113个受保护旧产物哈希未变。本次实验运行约5.94秒、峰值内存665MiB，单CPU线程，无GPU。真实研究运行的新官方验证访问及提前打开旧7月计数均0；独立核验的模型调用也为0。未修改既有模型或预处理，未提交、推送或部署。
