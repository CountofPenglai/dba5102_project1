## 1. 赔付字段含义与提前终止

### 1.1 `realizedProfit_USDC` 的解释

**当前解释（已获项目讲解转写支持）：**该字段表示平台向客户支付的赔付金额，不是平台利润。讲解在逐列解释和产品演示中均明确将该字段称为平台给用户的 payout（转写第 237–246、270–275、413–415 行）。这一业务含义已不再仅依靠数据相关性推断；但精确结算公式、价格源、费用及特殊情况仍未说明，转写也未核对原始录音。`premiumAmount_USDC − realizedProfit_USDC` 作为未计其他成本的订单收支差额，有讲解中“收保费、付赔付”的例子支持，不等于完整平台利润或正式评分公式。

支持证据来自对 7,079 条技术条件候选记录的回溯核对：

- Call 在上涨期间更常出现正赔付，Put 在下跌期间更常出现正赔付；不能用“上涨时是否为零”统一判断两个方向。
- 使用实际结算时刻之前最近的完整分钟价格，按 Call 的 `Q × max(S − K, 0)`、Put 的 `Q × max(K − S, 0)` 估算，零 / 正赔付判断与实际值的一致率为 **96.69%**。
- 每 BTC 赔付的平均绝对误差约为 **12.40 USDC/BTC**；改用合同到期时刻价格约为 **61.24 USDC/BTC**。实际结算时刻的价格更能解释记录值。
- 实际结算所在分钟的高低价对应赔付区间覆盖约 **92.98%** 的记录。这仅用于事后语义核对，包含该分钟内结算之后的信息，不能作为预测特征。

**处理方案：**按实际赔付开展后续研究，保留精确结算规则尚未确认的限制；不因简单期权公式无法完全拟合而删除记录。分钟价格近似、价格来源、结算规则等均可能造成差异，尚未确定各原因的贡献。

上述为本轮对话中的一次性核对统计，尚未加入固定审计程序；固定审计输出与该语义核对的口径不能混用。

### 1.2 提前终止与信息泄漏

**新增口述证据：**转写第 277–303 行明确区分持有至自动到期结算和用户中途主动关闭保护，后者可能出于兑现收益等多种原因。支持保留正常提前终止订单；不能由这段讲解推断全部提前终止记录都由同一原因导致，也未回答提前关闭是否包含时间价值、退费或其他调整。

**已确定的处理原则：**

1. 提前终止可能存在合理业务原因，第一阶段不要求逐笔解释原因，也不因正常提前终止而删除订单。
2. 定价时未知的 `closedAt`、实际持有时长、未来行情、持有期收益，以及“最终是否提前终止”均不能作为预测输入。
3. 定价时已知的 `createdAt`、`expirationDate`、`productType`、方向、执行价、数量及定价前行情，可以进入候选特征；基础价的使用边界见问题 2。
4. 已发生订单的实际赔付可以作为监督学习标签。目标是预测“给定定价时可见信息的预期实际赔付”，而非把事后结算时间提供给模型。
5. `closedAt` 可用于数据审计和判断训练时是否已获知标签。以时间点 `t` 训练时，采用 `createdAt < t` 且 `closedAt < t` 的有效结果记录。
6. 结算早于创建等逻辑异常与正常提前终止分开处理；异常记录进入审计标记，不混为用户正常行权行为。

**训练用法说明：**“最终赔付作为训练目标参考”在监督学习中意味着它作为标签 `y` 参与损失计算和模型参数更新。应禁止的是把同笔订单的最终赔付或其答案性变形放入输入特征 `X`，并非禁止训练使用标签。按照后来确认的逐日前向协议，测试期一笔订单的结果只有在结算后，才可用于未来日期的参数更新；不能反过来影响已产生的预测，也不能根据测试期表现重选特征、窗口、超参数或保守策略。具体规则见问题 10。

**实现状态：**审计及预处理保留正常提前终止订单，固定分割限制标签可获知时间；特征白名单不含终止时间、实际持有时长或最终赔付。初期不单独建立提前终止原因模型。历史赔付包含当时用户的终止行为，其分布若随定价策略变化，历史结果未必可以直接沿用。

## 2. 官方基础价的可比性与时间匹配

**已知事实：**

- 项目讲解称基础价主要来自 BSM（结合缩写与语境，将多处 “Black Show” 理解为 Black–Scholes）；实际成交保费还包含 CTA 类策略调整，例子包括 RSI、布林带。讲解未提供公式、波动率输入、利率、参数或完整策略代码。
- 官方指南声明三个追加价格字段在订单创建时可观测，并会保留在验证数据中。
- 历史 API Base 按相同方向和产品期限，匹配 **120 秒内最近的报价时刻**。这是最近时刻匹配，未明确限定只取订单之前的报价。
- 当前没有逐笔匹配报价的时刻、原始报价日志及完整 PP 转换规则。因此存在使用订单之后报价的可能，但不能判断实际发生比例，更不能称为已经证实的泄漏。
- `markup_per_BTC_USDC` 是成交单价减基础价的差额，可能包含价内外程度、PP 转换、补贴等差异，不能直接解释成平台配置的加价参数。

**已确定的处理方案（2026-10-07 确认）：**

- 第一轮接受 `apiBasePrice_per_BTC_USDC` 作为官方提供的基础价输入和比较基准，按当前已知资料推进基础价调整研究，把结论限定为“基于官方提供基础报价的离线比较”。不宣称已复现平台完整定价系统或证明报价可在真实时点重建。
- 比较策略使用相同订单和相同基础价；基础价是每 BTC 口径，换算订单金额时乘以 `quantity_BTC`。
- 我们自行构建的行情特征严格只取定价之前已结束的数据。
- 增加不使用 API Base 的风险预测对照，观察结果对该字段的依赖；该对照不能证明基础价本身不存在时点问题。
- 将匹配时刻、报价方向限制、执行价及 PP 转换关系列为待补资料；获得日志后再检验或重做仅向过去匹配，不凭空修正现有报价。

**仍待明确：**官方提供的历史成交价和 markup 是否用于新报价生成，需另行讨论；它们包含历史报价决策，不能仅凭“字段可用”就直接作为新定价的解释变量。本次确认不等于批准将全部价格字段直接输入模型。

**实现状态：**统一预处理将官方基础价作为可选特征；共同样本默认包含，风险口径不含，消融对照可在相同共同样本上移除该特征。历史成交保费和 markup 仅保存在元数据中。尚未实施基础价调整，报价匹配限制保留。

## 3. 基础价缺失与样本选择

**关键事实：**全部 7,204 条订单中，基础价缺失 **1,131 条（15.70%）**；集中于 5 月的 **237 / 965（24.56%）** 和 6 月的 **894 / 2,270（39.38%）**。技术条件候选样本为 **7,079 条**，可共同比较基础价的候选样本为 **5,955 条（全部订单的 82.66%）**。提供方在交付训练数据前还删除了 **627 条负 markup 记录**。

**已确定的三部分处理方案（2026-10-07 确认）：**

1. **共同样本做主比较。**使用当前 5,955 条基础价共同候选订单，后续按时间划分训练与验证，并按各截止时点限制标签可获知性。所有策略在同一批测试订单上比较；候选总数不代表任一窗口的实际训练量。
2. **缺失订单保留作风险研究。**不依赖基础价的赔付预测可使用更大范围的有效样本。基础价缺失不等于订单其他信息无效，但这些订单不能直接计算相对官方基础价的改善。
3. **第一轮不插补基础价，检查组间差异。**不填零，也不用历史成交价代替；优先在同一个月内比较缺失与非缺失组的期限、方向、数量及赔付分布，减少月份构成差异的混淆。事后赔付仅用于这类描述统计和合法训练标签，不作定价输入。

**资料限制：**保留筛选前后数量和覆盖率。研究结论仅适用于当前筛选后的样本，不能默认推广到提供方已删除的负 markup 订单或全部报价流量。

**实现状态：**已实现共同样本与风险样本的统一分割及加载，未插补基础价；已有分割与缺失数量统计。分割后风险样本 7,055 条，共同样本 5,934 条，区别于上方未经时间边界处理的候选数量。更详细的同月份组间差异分析和模型实验尚未实施。

## 4. 零赔付、大额赔付与保守余量

**关键事实：**有结果口径共 **7,150 条**，其中 **3,861 条（54%）** 赔付为零。最高 **72 条**记录贡献约 **33.01%** 的总赔付；72 是按有结果记录的 1% 向上取整所得。该口径包含部分时间异常，不等同于模型训练样本。

### 4.1 已确定的建模原则（2026-10-07 确认）

- 优先研究每 BTC 的预期实际赔付，再乘以订单数量得到预期总赔付。总金额集中可能来自大订单、较高单位赔付或两者共同作用；不能仅凭总金额最高 1% 的集中度断言单位赔付具有同样的尾部特征，应先分别检查。
- 比较直接预测预期赔付与“正赔付概率 × 正赔付条件均值”的两步方法，不预设后者一定更好。两步方法保留连续概率，不能先以 0.5 阈值把订单分成赔 / 不赔后再定价。
- 定价风险部分关注条件均值，不将它直接等同于最终报价。54% 为零并非严重的类别数量失衡；不因此默认需要过采样或类别加权，也不只用分类准确率或 MAE 选择模型。
- 同时检查单位赔付误差（如 RMSE，MAE 辅助）、实际数量加权后的总赔付偏差、按月份 / 期限 / 预测风险分组的校准及大额赔付表现。总体校准不能替代订单间风险区分能力；按事后赔付分组只能用于诊断，不能用于选择实际报价对象。
- 不为获得更好误差指标而直接删除或截断大额真实赔付；若训练中使用稳健处理，评价仍保留原始赔付并披露影响。

### 4.2 风险余量的研究方向

**用户已明确：**模型核心是估计赔付风险并适度高估，尤其在高风险场景下可以倾向于高估。接受保守取向，不等于所有订单统一涨价，也不等于要求每笔保费覆盖该笔事后赔付。

**已认可的分离原则及待实验确定的实现细节：**

- 保留一个可校准的每 BTC 预期赔付估计 `μ(x)`，另外记录非负风险余量 `b(x)`；保守风险成本记为 `c(x) = μ(x) + b(x)`。`x` 仅包含定价时可知信息。该表达式用于分清预测与保守程度，最终如何转换为基础价倍率及商业报价尚未确定。
- 高风险可由定价前波动、方向与执行价关系、剩余期限及模型预测的赔付分布等信息识别；训练样本覆盖不足或模型预测不稳定则属于估计不确定性，两者分开检查。不能用最终赔付或实际持有时长事后定义报价时的风险等级。
- 较高的预期赔付已经应当反映在 `μ(x)` 中；额外余量需要说明补偿的是尾部波动或估计不确定性，避免同一风险因素无依据地重复加价。高预期赔付并不自动意味着必须使用更高的百分比加价。
- 比较零额外余量、统一余量与风险相关余量，在同一测试样本及相同商业约束 / 需求情景下判断效果。保守强度在训练 / 验证期选择，冻结后再评估后期数据。
- 评价分别报告预期赔付预测的校准与加入余量后的价格、收支及留存变化。若直接使用偏重低估惩罚的损失训练，输出应称为保守风险估计，不能仍声称它是无偏的预期赔付。
- “适度”的具体上限和需求代价尚未确定，延续问题 7 的约束讨论；不以固定成交量下利润随价格上涨作为选择更大余量的依据。

### 4.3 当前倾向：高波动时更保守，低风险时保持现状

**用户当前偏好（2026-10-07）：**由于资料有限且产品供需关系未知，倾向于在高波动时期适度高估风险，在低风险时期保持现状。将其作为待验证的定价策略倾向，不作为已经识别的需求规律或已证明有效的结论。

**建议的具体边界，尚未定参数：**

- 波动状态只由下单前已结束的行情计算。窗口、阈值及余量强度只在训练 / 验证期选择，不能用整段数据或未来持有期波动定义当时的市场状态。
- 低风险时不额外增加这项波动风险余量；高波动时研究有上限、随风险变化的余量。低波动不自动等于低赔付风险，仍应考虑方向、执行价与市场价关系及剩余期限等信息。
- “保持现状”暂解释为维持选定的基准报价策略，以官方 API Base 为研究锚点；是否保留一个统一基础倍率尚待明确，不能直接把这句话等同于低风险订单按裸 API Base 收费，也不擅自改用历史成交价作锚点。
- 官方基础价可能已包含波动风险，具体机制尚不明确。应检查不同波动状态下基础价相对赔付的表现，以及额外余量的实际增益，避免仅凭波动高就无条件重复加价。

**实现状态：**建模原则、预测与余量分离的方向已认可；用户提出了波动状态相关的策略倾向。具体基准倍率、波动窗口与阈值、余量形式和上限、损失函数及评价参数尚未确定，未训练模型。

## 7. 需求不可识别与无约束涨价

**已明确的数据限制：**当前只有已成交订单，没有报价曝光、未购买记录或可用于选择行为识别的完整日志，不能可靠识别真实购买概率和价格弹性。

**新增口述证据：**讲解第 496–506 行直接承认不知道用户愿意支付多少，也难以量化价格与销量关系；第 119–124 行明确指出高价可能只在纸面上盈利，用户会停止购买，目标是更合理地定价风险并保持商业可接受性。价格下降可能增加购买是讲解中的定性判断，不是可用于拟合的需求数据或已经给定的需求函数。

在固定历史订单、数量和赔付不变的回放中，涨价会机械性提高收支差额；同一批订单若保费总额相同，总收支差额也相同。这类结果不足以证明定价更好。

**建议方案，待讨论：**

- 将赔付风险预测和最终报价选择分开，需求只作为明确声明的情景假设。
- 可用历史实际成交单价 `h` 作为留存情景的锚点，示例为 `a(p; λ) = exp[−λ × max(p/h − 1, 0)]`，其中 `h > 0`、`λ ≥ 0`。这是对既有购买者的假设，不是估计出的需求曲线；降价不凭空产生新客户。
- 情景收支差额使用 `Σ a(p) × (Qp − Y)`；不购买时保费和赔付同时不发生。该回放还假设购买后的数量与赔付行为可沿用历史值，需要披露这一限制。
- 提前固定低、中、高敏感度及风险与购买意愿相关的情景；所有策略使用同一套情景，不能挑选有利情景证明胜出。
- 可增加价格上限、成交留存下限或平均保费预算等研究约束，并与统一涨价策略比较。约束与情景参数尚未确定，不能称为官方规则。

**实现状态：**尚无需求模型、情景模拟或已批准的价格惩罚参数。

## 8. 如何证明优于官方 benchmark

**资料边界：**目前知道基础模型主要为 BSM、最终报价叠加策略调整，但没有代码、完整参数、明确数值评分公式或转换率函数。当前实际成交保费不等于官方 API Base。讲解反复强调基础价不是正确答案；模仿历史报价的拟合误差不能直接证明风险定价更优。

**建议比较框架，待讨论：**

1. 官方提供的 API Base，倍率为 1。
2. 仅在训练 / 验证期调优的统一倍率 `Base × c`，用于检验改善是否只来自普遍涨价。
3. 简单分期限倍率。
4. 根据定价时信息调整的动态模型；独立定价模型作为后续备选路线。

**新增比较建议，待后续实验落实：**增加历史实际成交报价的参考结果，用于代表已观察到的平台完整收费策略。与裸 API Base 分开展示；不能把“比基础价更好”直接等同于“比平台原有完整策略更好”，也不能用历史成交价当作正确价格标签。

所有策略在同一测试订单、相同成本口径、相同价格约束和需求情景下比较。分别报告预测质量、情景收支差额、留存、价格变化及分组稳定性。测试集不得用于选倍率或情景参数。

**结论边界：**阶段性结果只能表述为在明确数据口径和假设下的样本外改善；不能由固定成交量回放或单一需求情景推出真实平台利润和转化率必然改善。

## 11. 初版模型选择与可解释性

**用户要求与后续确认：**初步模型应具有较好的可解释性，同时能表达金融市场波动相关的复杂关系。用户已确认先记录并实现 GAM、EBM、浅层梯度提升树三类模型，保留明确训练入口与项目框架，暂不开始训练。最终选用哪个模型及超参数仍需后续验证。

**选择依据：**模型学习的是定价时信息与每 BTC 实际赔付条件均值的关系；波动预测准确不自动等于赔付预测准确。分钟行情数量不能替代带赔付标签的订单数量。以 6 月 1 日为例，前 30 天只有 935 条风险样本、702 条共同样本，且订单集中于少数期限，同期订单还可能共享行情冲击。因此优先共享不同期限的信息，限制自由度和交互数量，不按每个方向、期限分别训练复杂模型。

| 候选 | 建议作用 | 可解释方式与主要限制 |
| --- | --- | --- |
| 带平滑惩罚的 GAM | 第一轮解释性对照 | 用少量平滑曲线描述波动、剩余期限等与赔付的非线性关系；曲线平滑程度可控制，但纯加法结构不能自动表达复杂交互 |
| EBM（可解释提升模型） | 第一轮主候选 | 属于加法模型家族，用树提升学习各因素的非线性贡献，并可加入少量显式交互；比普通线性回归灵活，但细分过多仍会过拟合 |
| 浅层梯度提升树 | 后续效果对照 | 允许更自由的条件组合，限制树深和叶节点样本数；整体机制比 GAM / EBM 更难直接展示，事后解释不能替代结构透明性 |

**EBM 的初步设置建议：**先只用主效应，再比较最多两个有业务依据的交互——波动 × 剩余期限、方向 × 历史收益。不直接沿用大量自动交互的默认设置。GAM 和 EBM 先保持相同候选输入、历史窗口及原始单位平方误差目标，尽量单独检验模型结构的作用；减少高度相关变量同时进入所造成的解释不稳定。具体特征和正则化强度在验证期确定。

**零赔付处理是另一项结构选择：**先直接回归全部订单的单位赔付，再对较好的候选比较两步结构：`P(y > 0 | x) × E[y | y > 0, x]`。前者预测是否赔付的连续概率，后者只在正赔付历史上学习条件均值；二者都只使用当日可获知的标签。两步结构便于区分“更容易赔”和“一旦赔会更多”，但正赔付部分样本更少，不能预设优于直接回归，也不以分类阈值代替连续概率。

**波动与保守余量：**GARCH / EGARCH 可作为后续波动预测特征的来源，不直接代替订单赔付模型。现阶段先利用已有的事前波动与收益特征。用户偏好的高波动保守处理仍放在独立风险余量层；不据此强制实际赔付均值对波动单调递增。相关性、用户提前终止和样本选择都可能影响观察到的关系。

**比较与解释边界：**先完成 B0 / B1，再比较 GAM 与有限交互 EBM；浅层提升树、两步结构及替代损失留作后续受控对照。沿用逐日前向评估，所有变换只从当日合法历史拟合；用于模型选择和早停的验证也应遵循时间与标签可获知约束，不能直接依赖默认随机验证。6 月选择规则，7 月冻结规则后按天更新。除 RMSE、MAE、总赔付偏差外，检查不同日期、期限、事前波动组的表现，以及解释曲线是否随窗口剧烈变化。特征贡献表示模型内的预测关系，不等于因果作用；未见过的极端市场状态仍缺乏验证依据。
